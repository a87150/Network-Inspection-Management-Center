### 前端专项审查：剩下六条 P1

- **挂载 Vue 岛会清空表格勾选**。`mountPages` 结束时无条件广播 `app:modal-updated`，
  而 `workspace_table` 把它当成「数据变了，重取」的信号——于是打开问题明细、切任务中心

  广播带上 `detail.mount`，挂载不再算数据变化。
- **排序与翻页在请求未返回时点会错位**。`alert_list` 的 `sortBy` 先写 `sortKey/sortOrder`
  再 `load()`，而 `load()` 开头在 `loading` 时早退——箭头和 `aria-sort` 变了、数据没重取；
  再点同一列还会基于已改的状态反向，两个方向都拿不到想要的顺序。`jumpTo` 同样。加闸门。
- **表格请求乱序互相覆盖**。`workspace_table.request()` 没有序号也没有取消，连点两个列头
  会出现表头指向新列、表体还是旧列的排序结果，`loading` 也被先回来的那次提前置 false。
  加请求编号，只有最后一次有权写状态。
- **图表的 `role="img"` 把内部交互元素全吞了**。SVG 根上的 `role="img"` 会让所有节点的
  `role="button"`/`aria-label` 变成 presentational，读屏读不出；同时每条边都是 `tabindex="0"`，

- **每次刷新都让整棵 SVG 重渲染**。`syncControllerState` 每个 tick 都换新的 `expandedNodeIds`
  Set，而它参与 `visibleTopology` 等 computed——滚动、缩放、拖拽期间每个 tick 都跑一次
  全量 normalize + visible + layout（实测 80 主干 / 320 终端时 12ms 一次）。内容没变就复用旧引用。
- **滚轮与 resize 没有节流**。拖动平移早有 rAF 合帧，这两条漏了：滚轮一秒上百个事件、

## 2.36（2026-11-27）

这一版是域控流程的专项：四路并行审查覆盖了连接、同步、写操作、成员关系、
BitLocker、统计和 Web 层，改掉的问题里有四处会让功能整体不可用或误伤数据。
另修了表格工作区一处让两个前端测试长期为红的实现问题。

### 域控：同步范围收窄不再误停用账号
- 停用判定的依据从「base_dn 以内外都没见到」改成「本次 filter 与上次成功同步一致」。
  原来只挡了 base_dn 收窄；`user_filter` 改成带条件、或绑定账号只对部分 OU 有读权限时，
  实际命中集合变小而 base_dn 没变，一次同步就会把范围内没见到的账号整批写成
  `is_active=False`，首页的「正常/异常」计数直接反转。
- 同步任务现在把 `base_dn` / 三个 filter 存进 `parameters_snapshot`，执行时与上一次
  成功同步比对；不一致就只更新见到的对象，不推断谁被停用。

### 域控：三处会让功能整体不可用的问题
- **添加成员的候选范围**从 `distinguished_name__iendswith=base_dn` 改成按规范化 DN 在
  Python 侧比对。MariaDB 把它编译成 `LIKE '%base_dn'`，大小写取决于列排序规则
  （这套库是 `utf8mb4_bin`），而配置里的 base_dn 与 AD 返回的 DN 在大小写、逗号后空格
  上常常不一致——一旦不一致，候选列表恒空，「添加成员」这条路走不通且不报错，
  因为 DN 校验走的是 casefold 比较，配置本身合法。
- **组快照为空时跳过成员关系发布**。原来是拿到空快照就全删重建：`group_filter` 改成
  匹配不到、或绑定账号被裁掉 `member` 属性读权限（AD 静默省略属性，结果码仍为 0）时，
  `DomainMembership` 与全部 `group_names` 被清空，之后移出操作又被「不是已同步的直接
  成员」拒掉，界面上没法自救。
- **OU 归属的 DN 切分**只按未转义逗号切，不再用裸 `split(',')`。AD 里 CN 可以带逗号
  （改名成 `Smith, John`），裸切会把 `' John,OU=Sales,...'` 当 OU 写进库，PC 的组织
  归属从此一直是错的，而且每次同步都重写一遍错值。

### 域控：导入表格的两处资源耗尽
- xlsx 的列位置来自上传者可控的单元格 `r` 属性，写成 `r="AAAAAAAAAAAAAAAAAAAA1"` 就能
  让无界 append 吃掉几 GB 内存，而 20 MB 检查限的是解压后总大小、触发只要 30 字节。
  现在列号超出表格实际列数直接判解析失败，`_column_index` 对缺失/非法坐标返回 None，
  不再把 `str(None)` 的字母算成列号。
- CSV 分支补上与 xlsx 对齐的字节上限，先卡大小再 `read()`。原来一次读全量再逐行建 dict，
  100 MB 的表格能把 Web 进程打掉，而行数上限要等全部解析完才检查。

### 域控：批量操作的上限
- `MAX_DOMAIN_OPERATION_TARGETS` 从 500 提到 5000，与入队侧对齐。域账户上千是常态
  （批量停用离职账号、批量移 OU），500 会让这类操作直接拒绝且没有替代路径。
### 域控：第二批（安全、重试语义与导入）
- **明文绑定默认拒绝**。新增 Domain_Controller_Config.allow_insecure_bind（迁移 0079）。
  没开 SSL 又没勾这个开关时 connect() 直接拒绝——SIMPLE/NTLM 绑定会把域账号口令
  明文送上网络，而这个账号的权限通常远大于普通用户。存量现场能显式续命，且这个
  决定留在配置里可审计。
- **新建用户成功后回写本地镜像**。_update_local_mirror 原来对 create_user 直接跳过，
  导致导入阶段「登录名/DN 是否已存在」的检查对新建用户恒为假，同一份表格导两次会
  得到两批失败任务而拿不到任何冲突提示。现在用 get_or_create 落一行（is_active=False，
  AD 新建默认禁用），不覆盖已有行。
- **中断重试区分两种后果**。abort_password_domain_task 原来把 QUEUED 和 RUNNING 写成
  同一个 interrupted 标记，而重试门禁只认 stage 键，于是执行中的也能重放。
  现在排队中写 not_started（重放安全）、执行中写 manual_intervention_required（禁止重放），
  因为执行中被打断时 AD 侧可能已经 add 成功、只是密码没设。
- **写操作结果不确定时禁止自动重试**。move_ou 这类操作如果在读结果时抛异常，
  AD 里很可能已经生效，但原来记为普通 FAILED 并允许拿旧 DN 再发一次。现在标记
  write_result_unknown，重试门禁拦住并提示重新同步核对。目录明确返回错误码的情况
  仍按可重试处理——那是确定的失败。
- **批量操作上限 500 提到 5000**，与入队侧对齐。

### 域控：表单与前端
- **表单错误不再被压成一句话**。批量操作和导入校验失败时，字段级原因（缺密码、

- **计算机页签的动作不再被账户页签覆盖**。三个面板各有一份动作下拉框且共用同一个

- **must_change_password / password_never_expires 的目标状态改成三态下拉**

### 导入与外部连接：专项审查后修掉的五处
- **XML 防线可以绕过**（`net/infrastructure/xml_safe.py`）。原来只取前 4096 字节查
  `<!doctype`，而 XML 允许根元素之前出现任意长的注释——把 DOCTYPE 放在第 4096 字节
  之后就大摇大摆走过去。实测 5 KB 的 payload 能被 `ElementTree` 展开成上百万字符，
  四层嵌套即可撑爆 Worker。改成全文扫描（响应体本身已有 4 MiB 上限，代价可接受）。
- **人员回岗后离职日期永不清除**（`net/people/directory/sync.py`）。停用分支只在字段为空时
  写当天日期，而回到在职的路径不主动清，于是留下「在职 + 有离职日期」的自相矛盾记录。
  更麻烦的是 `_person_matches_record` 只在 record 带该键时才比较，这条脏数据之后每次
  同步都判 unchanged，永远自愈不了。现在在职且快照未带该字段时置空。
- **人员同步没有停用规模守卫**（`net/people/directory/sync.py`）。原来一次同步可以把大半个
  花名册标记离职，而这种批量停用几乎总是「范围被收窄」而不是「这批人一起离职」：
  收窄可能来自 `root_department_ids` 改动，也可能来自管理员在飞书/钉钉后台取消某个部门的
  应用可见范围——后者本系统零配置变更、没有任何痕迹，而定时同步又不经人工预览直接落库。
  现在停用数超过本地在职 50%（且在职 ≥5 人）时整份快照判为无效，提示核对根部门设置。
- **空采集项记成功**（`net/devices/network/snmp.py`、`net/infrastructure/http_collectors.py`）。
  `selected_items=[]` 时 `missing` 恒为空集，SNMP 与弱电 API 两条路径都落到 `success` + 空 data，
  巡检台因此虚增成功台数——与 `collector.py` 里「空请求不能记 success」的注释直接冲突。
  API 侧还会真的发一次 `?fields=` 空参数。现在显式空列表判 failed。
- **ifHighSpeed=0 丢掉有效的 ifSpeed**（`net/devices/network/snmp.py`）。RFC 2863 允许
  `ifHighSpeed` 返回 0 表示未知或小于 1Mbps，原来把 0 当有效读数，带宽显示 0 并连带把
  traffic 的利用率退化成 None。同一对 OID 在 `traffic.py` 里用的是「0 就回退」，两处语义
  相反，现在统一为回退。

### 导入与外部连接：审查发现但未修的问题
四路并行审查（导入链路、告警投递、人员目录、设备采集与门禁）共报出 2 条 P1 和 6 条 P2
尚未处理，都记在这里而不是悄悄放过：

- 告警投递泵零限流：worker 每轮 4 条、轮间隔 5 秒，约 47 条/分钟，是钉钉单机器人
  20 条/分钟上限的 2.3 倍。超限返回 130101 被判可重试，但重试固定 30 秒且所有重试行同秒
  齐发，三次之后写 FAILED，告警内容永久丢失且没有任何丢失提示。
- 告警重试窗口总共 60 秒，FAILED 之后没有任何重驱入口：`_claim_deliveries` 只领
  pending/retry/租约过期的 sending，`AlertDeliveryAdmin` 的 `has_change_permission` 恒为
  False，人工恢复只能改库。webhook 故障超过一分钟，这段时间的告警就等于全丢。
- Excel 模板的日期单元格被当成序列号原文。用下载的 xlsx 模板在「入职日期」里输入
  2026-01-15，Excel 存成 `<v>46037</v>`，导入报「time data '46037' does not match format」，
  整份文件被拒。模板样例行走的是 inlineStr，所以「模板样例可直接导入」那条测试恰好绕过。
- 更新式导入时，日期与数值列的空单元格会被当成「清空」：同一份 CSV 里文本列空着保留旧值，
  `hire_date`/`memory_total_gb`/`cpu_*_count` 却被写成 NULL，界面仍提示「更新 1 条」。
- 域账户导入把行级错误全部压成一句「域账户表格校验失败」，500 行的表只能人工二分。
- 上传体积上限在文件已完整落盘之后才生效，框架层与部署层都没有请求体上限。

这几条的共同点是改动会碰到语义（清空 vs 保留、限流阈值、模板日期格式），需要先定下来
再动手，不适合夹在本次修复里一起做。
### 导入与外部连接：又修掉七处
- **弱电设备告警渲染成 UUID**（`net/alerts/messages.py`）。`_asset_identity` 里有个
  `if target_type != 'monitor' else None`，把 `WeakCurrentDevice` 整个排除在外——
  而它本来就在 `TARGET_MODELS` 里。弱电设备告警永远显示「设备异常：5a175cc6-…」，
  设备名和 IP 全丢，值班人看不出是哪台机器。
- **恢复通知标题写成「设备异常」**（`net/alerts/templates.py`）。两种预设的标题都写死
  「设备异常：{device_name}」，状态行又是英文枚举，于是恢复通知和新故障长得一模一样。
  新增 `status_label` 变量，预设改用 `{status_label}：{device_name}`；用户自定义模板里
  写死的字段不受影响。
- **门禁 HTTP 状态码坍缩成一句话**（`net/access/adapters.py`）。`raise_for_status()` 抛的是
  `requests.HTTPError`，而调用方只把 `ValidationError` 当可读原因、其余记成
  「门禁平台采集失败（HTTPError）。」——401/403/500 和路径写错全是一句话。
  统一走 `_http_get`，连接错误和状态码都翻成可读的 `ValidationError`。
- **SNMP 配置错误被归成设备异常**（`net/devices/network/snmp.py`）。
  `validate_collection_settings` 原来在 try 之外，`ValidationError` 一路逃到
  `except Exception`，被归成 `response`，报「SNMP response error」且 `reachable=True`——
  运维会去查设备协议，而真正要改的是模板里的 scale 或 OID 名。现在归到
  `invalid_configuration` 通道（那个通道本来就有，只是没接上）。
- **厂商温度 OID 的 0/1 状态码被当成温度**（`net/devices/network/snmp.py`）。代码注释
  声称要挡「十分之一度和 0/1 状态码」，但判据只有 `-273.15 <= v <= 1000`——0 和 1
  恰好都落在里面，实测 0→0.0℃、1→1.0℃。现在单独排除这两个值。
  十分之一度那种没法从代码判断，已记进备忘。
- **设备 API 的失败原因被覆盖**（`net/infrastructure/http_collectors.py`）。只要状态不是
  success，message 就被改写成固定串「部分巡检项未成功；请查看各项证据。」，
  底层已经写好的 HTTP 401、超时、未配置 api_url 全部丢失。现在只在 message 为空时才填默认值。
- **认证失败被伪装成权限不足**（`net/people/directory/dingtalk.py`）。名字解析阶段的
  `except DirectoryAdapterError` 捕获了整个基类，认证过期和限流也被改写成
  「请检查通讯录可见范围及读取权限」——运维照着去后台开权限，而真正该做的是重新授权。
  现在 `DirectoryAuthenticationError` 和 `DirectoryRateLimitError` 原样抛出。

### 导入与外部连接：两处导入缺陷
- **域账户导入表头带空格就整列读空**（`net/domain/user_import.py`）。校验用 strip 后的
  名字、取数却用原始名字，于是「登录名 」能通过必填列检查，随后整列读成空串，
  报「第 2 行存在空的必填字段」，用户对着一列填满的登录名找不到问题。
  现在校验和取数共用同一套名字。
- **导入报错行号不是文件真实行号**（`net/data_exchange/inventory_csv.py`）。
  `enumerate(reader, start=2)` 数的是 csv 记录数，而 `DictReader` 会静默跳过空行，
  空行之后的行号全部偏小。改用 `reader.line_num`。

### 需要实机验证的清单
- 新增 `docs/integration-manual-checks.md`：九条只能在对端环境里定论的问题（飞书入职时间
  字段、根部门 ID 的形态、两家的业务错误码、十分之一度的温度 OID、Excel 日期单元格式、

## 2.35（2026-11-27）

### 采集状态不再被「本就不支持」拉低
- `config_info` 是入队时强制加的每日配置备份，但原生配置只支持 Cisco 和 H3C。
  以前不支持的厂商（华为、锐捷、通用交换机，以及非大华的弱电设备）会被判
  `partial`，接着写一条 `Error_*`、记一次异常、每轮再补一条 critical 采集告警。
  现在 `unsupported` 算「本就不适用」，不参与缺失判定（`ssh_collectors.py`、
  `http_collectors.py`）。这类设备终于能显示正常。

### 「数据不足」从「正常」里分出来
- 采到回显但算不出结论时，以前判 `unknown` + `info`，健康度只认「非 info」，
  于是首页显示绿色、写不进 Error、也不会告警。新增 `health_status="incomplete"`，
  汇总里单列 `incomplete_count`，既不进正常也不进异常——它既不是好也不是坏。

### 后台作业不再被一条异常打死
- `worker.run_forever` 以前只 catch `OperationalError`，主线程里的清理、对账、
  排计划调用只捕获 `ValidationError`。任一条 `IntegrityError` 或 `ValidationError`
  冒出来就整个进程退出，队列和告警一起停。现在维护段逐块包边界，主循环兜底
  记日志后继续。

### 库存回写失败不再吞掉采集结果
- `refresh_asset_inventory` 跑在采集事务里，它抛异常会把巡检记录、Error 行、
  target 终态一起回滚，target 停在 `RUNNING`，重试三次后只留下一条「租约过期」。
  现在与配置备份用同一层隔离，库存写失败只记日志。

### 模板与计划
- 弱电模板匹配补了通配回退：精确 → 同厂商任意类型 → 任意厂商同类型 → 通配。
  以前只回退到 `(vendor, "")`，而种子模板一律 `vendor=""`，填了厂商的设备
  拿不到种子的采集项和阈值。
- 停用的父模板不再继续被继承（`template_settings` 沿父链检查 `is_enabled`）。
- 计划里被停用的设备只从本轮范围剔除，不再让整个计划永久抛错；配置错误的
  计划按正常节奏推进 `next_run_at`，不再每个 poll 重试一次。

### 目标级执行互斥
- 同一台设备同一时刻只允许一个活动任务采集它。以前 task 级 `scope_key` 含
  目标 id 列表，目标集合一变就换键，「A+B」和「A+C」能同时跑，A 被采两次，
  落两条记录、发两条告警。
- 目标级互斥本身一直是有效的：`0040_mariadb_active_target_scope` 用 `STORED` 生成列
  `net_active_execution_scope`（活跃态取 `execution_scope_key`、终态为 NULL）加唯一索引
  `net_target_active_scope_mysql`，补上了 MariaDB 不支持条件唯一约束（`W036`）的缺口，
  数据库层真实生效。这轮加的是入队时的**显式预检**，价值在于把「数据库拒绝」换成
  能指名设备的提示，不是补一个漏洞。

### 告警保留
- `AlertEvent` 不再列为任务清理的 blocker：每个终态巡检任务都会建一条 summary
  事件，把它当 blocker 的结果是所有任务都删不掉、历史无限增长、清理每轮空转。
  现在任务过期时连它的告警一起删（投递行是 CASCADE）。

### 其他
- 配额等待超时写进 `error_message`，不再只留进程日志，也不会被笼统记成「租约过期」。
- `traffic` 里没有端口带宽的接口不再让整项卡在「数据不足」：只要还有接口能判且

- `alert_items` 不再被无条件丢弃，「按设备关闭告警项」真正生效；空列表视为未配置。
- 无适用项判空时排除强制的 `config_info`，模板把指标全标为不适用时任务不再静默空转。

- **温度读数**加范围校验（-273.15–1000℃）：厂商 OID 常返回十分之一度或 0/1
  状态码，以前会直接当 ℃ 用，得到假读数或假超阈。
- **严重级别**改按 `analysis_item` 判关键项（`domain_trust`、`cpu_health`、

- **空目标集**不再判成功：`0 == 0` 会让一个什么都没跑的任务显示 100% 正常。
- **清理头部饥饿**：先切片再过滤会让最老一批被拦住的记录永久堵住入口，现在多扫
  几倍并删够即停。
- **没有 task_target 的记录**不再静默泄漏：它匹配不上任何 join 条件，以前既不

- **计划 DST 兜底**：`make_aware` 遇到不存在的本地时刻不再让整个计划抛错。
- **任务总结**里对同一条查询的重复求值收敛为一次。
- 渠道停用的说明文案从英文改为「渠道已停用，未发送。」，与「发送失败」区分。

### 复查后撤回的三条
- 「`RETRY` 显示成 `PENDING`」不成立：`AlertEvent.Status` 本来就没有 `RETRY`，
  投递行在重试时事件仍是待发送，语义正确。
- 「收尾与续约时钟不一致」不成立：两者都用 `timezone.now()`；`renew_lease` 里
  那个 `Now()` 是刻意的锁内 fence，注释已写明。
- 「持续故障每轮重复通知」不成立：`get_or_create` 按 `target_run` 去重，每个任务
  最多一条事件，一轮巡检通知一次是应有的。
### 上千台设备不再被入队上限拒绝
- 单任务目标数上限从 500 提到 5000。上千台设备是常态，原来一个「全量」计划
  在超过 500 台时会直接抛 `ValidationError`，而计划侧不推进 `next_run_at`，
  结果是一个永远不会成功的计划，每 5 秒重试一次、写一条错。
- 目标行改成 `bulk_create` 分批写入（每批 200）。原来是一条条 `save()`，
  在一个事务里发 N 条 INSERT——注释里写着「5 万条能把 worker 卡住」，但那个
  逐条 save 一直没改成批量，上限只是把症状挡在了 500。
- 域控任务仍走逐条 `save()`：`TaskTargetRun.save` 里对域控快照的敏感值检查
  是唯一做这件事的地方，`bulk_create` 会绕过它。
- 入队前的「目标是否正被别的任务采集」预检改成按批查，避免一条几公里长的
  `IN (...)`。
- 新增测试：1200 台设备进一个任务（`total_targets` 与目标行数一致、每个目标
  都有互斥键），以及超过 5000 会被拒。

## 2.34（2026-11-26）

### 域同步的停用范围
- 收窄目录搜索范围不再误停用范围外账号。原来 `Domain_Account.objects.exclude(
  login_name__in=seen_accounts).update(is_active=False)` 是全表操作，搜索起点改成
  某个 OU 之后，「范围内没见到」等于「该停用」，范围外的账号会被整批标成本地停用
  （不会去 AD 禁用，但统计、活跃账号列表、缺失登录判定全部跟着错）。
  现在只在 `base_dn` 子树内停用，`base_dn` 为空时一律不动。计算机同规则。

### 维护窗口的抑制口径
- 维护窗口改成「剔除」语义：汇总通知照发，但维护中那台设备不再计入
  `total/normal/abnormal/failed/cancelled/skipped/info` 七个计数，也不出现在
  「故障示例」和「恢复示例」里。
- 删掉投递层那段永不生效的 `exclude`：summary 事件的 `target_type` 恒为
  `'task'`，与 `MaintenanceWindow.TargetType` 的三个资产类型永不相交，
  它从上线起就没有拦下过任何一条。

### 告警通知模板可以有多套
- `AlertNotificationTemplate` 去掉单行锁死（`key` 主键 + `CheckConstraint`），
  改成用 `id` 主键的命名模板，带 `trigger`（`summary` 任务汇总 / `device`
  单设备告警）与「每种 trigger 一个默认」的唯一约束。迁移把原来那一行转成
  「默认任务汇总」，数据不丢。
- 新增 `AlertChannelTemplate` 绑定表：模板和渠道之间多一层，一个渠道可以绑多套
  模板，`(channel, trigger)` 唯一。这样同一个 webhook 只配一次地址和密钥，
  想发两种内容就挂两条绑定，不用把 webhook 抄两遍。

### 单设备告警
- 补上单设备通知链路。原来 `abnormal` / `recovery` 事件只写 `status='recorded'`，
  **从不创建投递行** —— 系统里只有任务结束后的汇总，没有任何「某台设备出问题了
  就通知」的路径。
- 判定条件：该渠道绑了 `trigger='device'` 的模板才发；没绑就不发，不会因为
  建了个渠道就把每台设备的异常都推一遍。设备在维护窗口内时同样不发。
- 发送时按渠道模板渲染：`build_alert_message(event, channel)` 现在会用
  `resolve_template(channel, 'device')` 渲染标题和正文，变量集是设备维度
  （`{device_name}` `{device_ip}` `{target_type}` `{status}` `{occurred_at}`
  `{tasks_name}` `{issues}` `{recovered_count}` `{details_url}`）。
- 任务汇总也改成按渠道渲染：同一份汇总发给两个渠道时，两个渠道各用自己绑的模板。

### 告警投递与资产写入
- 邮件渠道的投递租约从 30 秒延长到 300 秒。SMTP 握手 + TLS + 大附件经常超过
  30 秒，租约到期后另一个 worker 会把同一条重新领走，用户收到两封一样的邮件。
  webhook 仍是 30 秒。
- 入队加目标数上限（500）。原来逐条校验、逐条 save 且没有上限。
- 停用/启用改成幂等：表单带目标状态而不是让服务端「反过来」，重放同一个请求
  不会把设备又切回去。老调用方只传 pk 时仍按翻转处理。
- 设备编辑加乐观锁：表单带 `form_revision`（`updated_at`），提交时与库里比对，
  不一致就拒绝保存。两个人同时改同一台设备时，后保存者过去会整体覆盖前者，
  还会把巡检刚刷新的 `os_version` 改回旧值。
- CSV 导入的主键冲突单独提示。以 IP 为主键时是「先查后插」，两人同时导入同一批
  数据会撞唯一约束，原来一律报「数据库写入失败」，用户会反复重试同一个文件。

### 界面
- **模板和渠道的配对挪到了告警策略上**。策略里每个渠道各配「任务汇总模板」和

### 拓扑绘制
- IP 解析不出网段的终端不再静默消失：没有物理父节点也推断不出子网时，兜底挂到

  直接跳过，节点没有 `parent_id` 前端就不画，而顶部「另有 N 个设备未绘制」只统计

- 画布拖动改成每帧提交一次（`requestAnimationFrame` + `pendingPan`）。原来每个
  `pointermove` 都整体替换 `viewport`，整棵 SVG 跟着重渲染。

## 2.33（2026-11-25）

### 巡检采集口径
- 「能力不支持」不再降级巡检状态：弱电、sangfor、未注册厂商返回
  `status='unsupported'` 时，过去会把 success 降成 partial（data 只有
  config_info 时直接 failed），这些机器每天第一次巡检必然 partial。
  「不支持完整配置备份」这条 finding 保留，但不再算失败。
- 空请求或不可达不再记 success：弱电、sangfor、网络设备三个采集入口在
  `selected_items` 为空时都返回 success，而实际既没连上也没采到任何东西。
- 入队拒绝空 `selected_items`：过去能建出任务，服务器会正常连一次 SSH、
  循环为空、记 success。
- Linux 的命令级错误不再丢：原因写在 `raw['command_errors']`，而落库只认
  `collection_errors`，exit code 和 stderr 进不了 details。
- 拓扑批次创建移进采集 try：`begin_topology_batch` 抛错会把一次没跑的采集
  记成 FAILED；`payload is None` 的路径也补上错误留痕。

### 维护窗口与资产写入
- 批量建窗口下沉校验：REST 侧过去完全不校验 `target_ids` 存在性，可写孤儿
  窗口；同一资产同一时段可重复登记。现在存在性校验 + 区间去重都在共用的
  `create_windows` 里，用事务包住。
- 维护方块四桶相加等于总数：停用且未结束的窗口过去落在三块之外。
- 停用/启用接口非法 pk 返回 404 而不是 500。
- 服务器端口留空的错误提示不再指向 IP。

### 配置备份
- 历史 / 对比 / 下载三个页补上入口：视图功能完整但全仓零反链，用户只能手打 URL。
- 对比页候选收窄为「比当前更旧」：选中更新的版本会让旧/新标签和 +/- 行数
  整个反转。手工构造 `?against=<更新版本>` 会明确 404。
- ZIP 超 500 台时报告实际台数，不再统一回「请选择有效的设备」。
- manifest.csv 拆列：一列过去既写 scope 又写错误文案，现在拆成 `scope` + `notice`。
- 差异表截断优先保留变更行：差异靠后时用户看到「新增 N 行」却找不到变化。

### 告警投递
- 钉钉 / 飞书的限流被记成永久失败：两个适配器对响应体里的 `errcode != 0` /
  `code != 0` 一律判不可重试，但限流是 **HTTP 200 + 响应体错误**（文字是
  「send too fast」），5 次上限内一次都不重试，突发时直接丢告警。改成按响应体
  里的限流措辞判定，不硬编码错误码。
- 一行坏数据让整条投递队列停摆：取行和渲染原来在 `try` 外面，channel.settings
  解密失败或事件序列化异常会逃出 for 循环，本批剩余行不处理；claim 按创建时间
  排序，坏行每轮都在队头。移进 `try`，单行失败只记 warning。

### 设备表单与维护窗口
- 服务器「SSH 端口」留空必然保存失败：`port` 统一改成非必填，但 `Server.port`
  是 NOT NULL，None 一路落到 INSERT，最后被翻译成「请检查 IP 是否已存在」。
  改成按模型列是否允许 NULL 决定必填性。
- 删除维护窗口的 `next` 是开放重定向：收到外部地址会原样 302 出去。已加
  `url_has_allowed_host_and_scheme` 校验。

### 知识库与检索
- 长文档切段会重复一整段：`split_chunks` 追加后没清空缓冲，进入按行切的分支时
  旧内容被重新拼进去，同一段入库两次、检索时占两个结果位。
- 表格导入吞掉正文换行：先 `splitlines()` 再喂 csv，跨行引号字段的分隔符插不回去。
  改成 `csv.reader(io.StringIO(text))` 直接吃原始文本。
- 知识库删除接口读 `request.POST` 而前端发 JSON，永远取到空 id；非法 id 还会让
  `filter(pk='')` 抛 ValidationError 变成 500。改成解析 JSON 并把非法 id 挡成 404。
- 向量检索故障被当成「越权提问」：所有异常都吞成空列表，连「没配 AI 服务」也一样。
  现在没配单独上抛，其余降级并记 warning。
- AI 接口的错误原因前端看不到：后端用 `error` 字段，前端只读 `message`，
  提示全退化成「请求失败（400）」。两边的字段名现在都认。

### 列表与权限
- 只读账号在首页任务栏翻页、拓扑页 IP 查询都 403：两个纯 GET 视图漏在
  `READER_VIEWS` 外面。
- 告警列表切列排序方向相反：`sortBy` 先记列名再算方向，导致「同一列」判断恒真，
  切到新列会沿用上一列的方向取反，提示文字也跟着说反。
- 首页卡片可能重复出现同一个按钮：`detail_url` 的判断写了两遍，第二个分支没有保护。
- 维护页 `can_administer` 写死 True，非管理员看到删除按钮点了才被拒。
- 任务栏的「获取成功」恒为 0（`_outcome_expression` 根本不产出这个桶），
  异常中心的「未处理」恒为 0（常量占位）。两个死字段一起删掉。
- 网络/服务器/弱电页的勾选列只给管理员，只读账号无法反选或导出所选；
  PC 日志页的筛选控件不跟随地址栏，筛选生效但控件显示未勾选。

### 资产与巡检口径
- 巡检方块的「正常/异常 N 台」数的是记录条数：同一台设备巡检 3 次算 3 台，
  数字随重跑次数虚高。改成台数取资产表、异常按每台最新一条记录的严重级别算。
- 采集结果的接口表 / VLAN 表把「部分成功」标记丢了，一条命令失败仍判 success，
  巡检结论把不完整当正常。现在顶层带 `status: partial`，完成度判定能识别。
- 端口总数 / VLAN 数量永远填不上：采集器不产出这两个键，现在从表长度回填，
  并且只认完整的表。
- 生产路径的 SNMP 采集没有总超时，慢设备单台能跑几分钟、占死 worker 池。
- 失败状态写入本身出错时被静默吞掉，设备会永远停在 RUNNING、最后被误判成
  「租约过期」。现在记日志。
- 等待命令行并发配额超时被当成「采集失败」计入异常率且不重试，实际根本没连过设备。

### 记录页与任务栏
- 巡检记录页点历史任务时，标题换成所选任务、表格却还是最近一次的记录，
  导出也一起错。后端现在解析 `task` 参数。
- 任务栏翻页后行点击失效：点击处理器绑在任务栏元素上，翻页是整块换节点。
  改成委托到 document。

### 删除与凭证
- 有拓扑数据的设备在 admin 里删不掉：拓扑外键是 `PROTECT`，Django 的
  `delete_selected` 只要看到 protected 非空就直接拒绝，`delete_queryset`
  里那套「先删观测→链路→接口→批次」的清理永远轮不到。现在在确认页阶段
  就把设备独占的拓扑行算作「一起删掉」，其余受保护关联照旧按原样拦。
- 以 `gAAAA` 开头的明文口令不会被加密：`encrypt` 原来只按 Fernet 前缀判断
  「已加密」，命中就原样入库。这类口令之后再读出来会抛 `ValueError`，
  那台设备的详情、巡检、编辑全部报错且用户自己修不了。改成先试着用当前 key
  解密，解得开才算真密文。

### 会话与缓存
- 会话过期后所有 AJAX 静默返回 `null`：页面视图回 302 → `/login/`，
  fetch 跟随后变成 200 的 HTML，`readPayload` 返回 `null` 却被当成功载荷，
  调用方接着在 `payload.results` 上抛 `TypeError`。现在识别重定向到登录页
  和 HTML 响应，统一抛「登录已失效，请重新登录」。
- 页面缓存对真实浏览器完全不生效：`GZipMiddleware` 排在缓存中间件之后，
  `process_response` 反向执行时先给响应加了 `Vary: Accept-Encoding`，
  而 Vary 允许集合里没这一项，带 gzip 的浏览器响应永远判不合格、一次都不写。
  把 `accept-encoding` 加进允许集合，并纳入缓存身份，不同编码偏好分开存。

### AI 配置读写
- 上下文压缩一启用就 500：`call_model` 返回的是 `(正文, 用量)` 二元组，
  摘要那行把整个元组当字符串拼接，消息超过 20 条后每轮提问都报错。
  改成只取正文，并把写回摘要的动作圈进 `try`，压缩失败的旁路不该带崩提问。
- 保存配置会清空没提交的字段：输入区切一次模型（只发 `chat_model` 和
  `reasoning_effort`）会把接口地址、模型名列表、Embedding 模型、检索方式、
  两个阈值、保留条数全部写成空。`save_settings` 改成只改 payload 里出现过的键。
- 切换提供方看起来成功、实际没换：`ai_config()` 先用激活的那组覆盖，随后
  又被 `AiSetting` 里的旧值盖回去。改成提供方优先，`AiSetting` 只补它没给的项。
- 弹窗的「保留最近消息」「压缩触发条数」「思考模式」三个控件存不进去 ——
  表单里有、控件也在，但保存时没提交。补上这三个字段。
- 切换或删除提供方后，把生效那组的端点/密钥/模型镜像回 `AiSetting`。
  不镜像的话，切到一组只填了模型名的配置时，地址会沿用上一组的值；
  删光所有组后也清不掉旧地址。

## 1.58（2026-11-19）

修掉资产列表整片空白，并把同屏多表的分页筛选做全。

### 空白页的根因

`list.html` 的 `page_scripts` 块在 1.54 改模板时丢了 `<script type="module" src="app/vue/boot.mjs">`。浏览器拿不到 boot 模块，Vue 岛永远不挂载，表格区就是一片空白——服务端 payload 里躺着 20 行 926 条，页面上一个也看不见。补回该标签后五类资产列表恢复正常。

这个 bug 是测试抓不到的：断言全在服务端，DOM 挂载属于浏览器行为。教训记在这里——改挂载点所在模板时，`page_scripts` 也要一起看。

### 表查询层的前缀已经有了，只是没用

`index/common/table_query.py` 本就支持 `prefix`：`apply_table_filters(..., prefix='accounts')` 会读 `accounts_filter_*` / `accounts_page` / `accounts_sort`，`table_state['parameter_names']` 也已经按前缀生成，`common/table_workspace.html` 用的正是这套名字。所以这次没有改查询层，只是把它用起来。

域控三个页签各用 `accounts` / `computers` / `groups` 前缀，PC 的采集异常用 `errors` 前缀，各自的分页、排序、筛选互不干扰。旧的无前缀链接由 `_alias_legacy_parameters()` 补成别名，书签不会失效。

### PC 分析记录不是表格

原以为 `/computers/analyses/` 是表格页，实际它是任务与统计视图，字段来自分析结果而非资产快照——`computer_logs` 表定义对应的是 `ComputerLogFile`，套到 `ComputerAnalysis` 上直接 `FieldError: Cannot resolve keyword 'platform'`。所以「分析记录」页签给的是最近八次分析与总数，完整视图仍在 `/computers/analyses/`。「采集异常」是真正的表格，带完整筛选与分页。

同一实体的列表、统计、详情与专属操作面收进一个页面。

## 1.2.0（2026-11-17）

### 设备命令行并发上限

巡检配置里的 `concurrent_workers` 只约束一个任务。两个巡检同时跑、或单个配置设得很高，就会把被巡检交换机的 VTY 打满，现场表现是大面积登录失败，排查方向会被带到"凭据错误"上去。

新增 `NET_SSH_CONCURRENCY`（默认 10）与进程内信号量，在任务线程进入执行前占位，超时按"等待并发配额超时"记录，不无限阻塞。网络设备与服务器同池——两者都可能开 SSH 会话；弱电设备走 SNMP/HTTP，不进池。

信号量是进程内的，N 个 Worker 进程就是 N 倍预算。这条天花板有意保留并写在代码注释里，升级路径是换 Redis 计数。

### 配置版本对比与变更行数

配置备份一直有 10 个历史版本，但没有任何对比入口，只能下载两份到本地用其他工具比。新增按行对比：`difflib.SequenceMatcher`、`autojunk=False`（配置里重复短行多，开启popularity 启发式会错位整块）。对比页只有管理员可见，**不做脱敏**——打掉 `enable secret` 那几行，正好藏住运维要找的改动。

同时修掉一个契约冲突：备份历史页有一项既有测试断言"历史页绝不解密"。变更行数改在**写入时**算好，落库为 `change_added` / `change_removed` 两列，列表页直接显示 `+N / -M`，不再解密。迁移 0067。

### 告警维护窗口

给单台网络设备设定计划变更时间段，窗口内的告警**照常生成、照常入库，只是不投递**：投递行保持 pending，历史里能看到"当时确实告警了、被窗口压住"。窗口结束若仍在重试范围内会自动发出。

判断点在 `_claim_deliveries` 抢占之前，因此摘要类与单目标类两条投递路径都生效。区间为半开 `[start, end)`，全部在 Python 侧按 `settings.TIME_ZONE` 计算——`net.W001` 未解决，数据库时区函数会求值为 NULL。迁移 0068，录入入口在运维管理台。

### IP 定位

ARP、MAC、LLDP、路由表本来就是交换机/路由器/AC/AP 的默认巡检项，证据每天都在采，只是没有查询入口。新增按 IP 或 MAC 反查：返回哪台设备的哪个接口、哪个 VLAN、哪次巡检、什么时候。

不改采集、不加扫描：只读各设备最近一次成功巡检结果，默认回看 7 天，MAC 比较忽略分隔符（`aa:bb:cc`、`aabb.ccdd.eeff`、`aabbccddeeff` 等价）。页面明确标注 ARP/MAC 是被动观察，只证明某次巡检见过，不证明此刻在线。

### 未包含

IP 台账与 Vue 岛屿按约定放到 1.3.0。

## 1.1.0（2026-11-17）

### 网络设备新增 Telnet 传输

命令行会话有 SSH 与 Telnet 两种传输，由设备的「命令行协议」二选一，互斥：同一个 Netmiko 会话只换传输层，命令表、分页处理和解析完全复用，没有第二套采集实现。Netmiko 对每个已映射厂商都提供 `_telnet` 驱动（Cisco、H3C、Huawei、Ruijie 与通用终端），切换传输不需要改模板、命令或解析。

Telnet 是明文协议，账号口令与采集内容在链路上可读，只用于确实没有 SSH 的老设备。

## 1.0.0（2026-10-04）

### MariaDB / PostgreSQL 双数据库

`DB_ENGINE` 取 `mysql` 或 `postgresql`，正式环境和模拟环境共用同一份 `.env`，改一个值即可整体换库。
两种后端跑同一套迁移、同一套测试。`psycopg[binary]==3.3.6` 进入 `requirements.txt` 与锁文件。

为了让同一份代码在两个后端上行为一致，修掉了这些后端差异：

- `JsonKeyType` 补齐 PostgreSQL（`JSONB_TYPEOF(JSONB_PATH_QUERY_FIRST)`）和 SQLite 分支。
  用 `_FIRST` 是因为 `JSONB_PATH_QUERY` 是集合返回函数，放进 `CASE` 会报类型不匹配。
- 去掉三处 `select_for_update()` + 可空外键 `select_related()` 的组合（`DomainOperation.task`、
  `Schedule.people_source`、`Schedule` 的四个档案字段）。PostgreSQL 拒绝在外连接可空侧加锁。
- 设备配置备份的文件名在落库前剔除 NUL：MariaDB 收得下，PostgreSQL 报 `DataError`，Windows 本身也不允许。
- 告警策略的 upsert 按后端能力决定是否传 `unique_fields`。

### 域控同步纳入告警

域控同步失败此前不产生任何告警：告警白名单只认巡检和日志分析两种任务类型，而域控同步按 DC 配置分作用域，
既没有档案也没有可映射的外键。现在 `result_type='domain_sync'` 会生成 `execution.failure` critical 告警，
并在同步结果落库后立即评估，不用等 worker 下一轮。

### 人员自动同步纳入告警

和域控同步同样的漏网：`ALERTED_TASK_TYPES` 里没有 `people_sync`，人员自动同步失败不产生任何告警。
现在按同步源分作用域（`people_source`），同步结果落库后立即评估，不用等 worker 下一轮。

### 界面

域控连接设置页的「启用定时同步」改用与右侧间隔输入框一致的开关卡片样式。
