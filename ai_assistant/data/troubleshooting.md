# 网络故障处置手册

面向巡检平台的运维提问整理。每条都按「现象 → 排查步骤 → 处置」写，
现象是可观察的，排查步骤是能在本平台和设备上真正执行的命令。

## 交换机端口 down 导致单台终端断网

- 现象：同楼层其他终端正常，只有某台 PC 无法上网；巡检记录里该 PC 离线，交换机对应端口状态为 down 或 err-disabled。
- 排查步骤：
  1. 在巡检平台打开这台交换机最近一次巡检记录，看 interface_status 里目标端口是 down、err-disabled 还是 up 但无流量。
  2. 登录交换机执行 display interface GigabitEthernet0/0/1（华为、华三）或 show interfaces GigabitEthernet0/1（锐捷、思科），确认物理状态、速率和双工是否与对端一致。
  3. 端口为 err-disabled 时看 display interface brief 的 cause 字段，常见三种：BPDU protection（接了路由器或私接交换机）、loopback detection（环路检测）、port security（MAC 数超限或违规）。
  4. PC 侧 ipconfig /all 确认是否拿到 IP 和网关，先排除 DHCP 与地址池耗尽。
- 处置：人为触发的 err-disabled 要先排除环路或违规设备，再 shutdown / undo shutdown 恢复；同一端口反复触发，改 port security 上限或关闭环路检测，不要靠反复重启端口掩盖问题。

## 交换机 CPU 占用持续超过 90%

- 现象：巡检 cpu 项报异常（默认阈值 90%），设备命令行响应变慢，业务出现丢包。
- 排查步骤：
  1. 巡检平台看该设备 CPU 曲线是阶跃升高还是缓慢爬升，阶跃通常是突发流量或环路，爬升通常是持续放大的广播、ARP 学习或有进程死循环。
  2. 执行 display cpu-usage（华为）、display cpu-usage（华三）、show processes cpu sorted（锐捷、思科），定位占用最高的任务。
  3. 若 CONTROL 或 ARP 任务高，查 display interface 的广播包速率和 display mac-address 里是否有同一 MAC 出现在多个端口。
  4. 若某端口 input 速率持续打满，用 display interface 看该口流量，确认是哪台终端或环路。
- 处置：环路端口先隔离并启用 STP、BPDU 保护；广播包占比超过总流量 5% 时查 VLAN 内主机；管理面被扫描时在 ACL 上限制源地址；确认是路由震荡引起的，收敛慢的接口调 BFD 或路由协议定时器。

## 端口 CRC 错误与光模块衰减

- 现象：业务时断时续，大包传输更容易失败；巡检 traffic 项显示该接口丢包或有错包。
- 排查步骤：
  1. 在交换机执行 display interface 看 Input errors、CRC、Giants、Runts 计数，隔 1 分钟再看一次，判断是否持续递增。
  2. 光口执行 display transceiver interface（华为、华三）或 show interfaces transceiver（锐捷、思科）读收发光功率，接收功率接近灵敏度下限或低于 -20dBm 说明链路衰耗过大。
  3. 检查两端速率和双工：一端自协商、另一端强制固定是最常见的半双工冲突来源。
  4. 更换跳线、清洁光口端面，排除跳线和法兰污染。
- 处置：CRC 每分钟新增上百必须处理，不能只观察；先换跳线再换光模块，最后考虑熔接衰耗；两端统一为自协商或统一强制，不允许一端强制一端自协商。

## IP 地址冲突

- 现象：终端间歇性断网，系统日志报「检测到 IP 地址冲突」，网关 ARP 表里同一 IP 对应两个 MAC。
- 排查步骤：
  1. 在接入交换机执行 display arp | include 10.20.30.40，拿到冲突 IP 当前的 MAC。
  2. 执行 display mac-address | include MAC 地址，看这个 MAC 从哪个端口学到，是否有两个端口同时学到同一 MAC。
  3. 到 DHCP 服务器查该 IP 是否落在地址池内，同时被静态配置给了另一台设备。
  4. 逐台终端用 arp -a 和 ipconfig /all 核对，找出手工配置了同网段 IP 的主机。
- 处置：把手工静态地址从 DHCP 地址池中排除，或给服务器、打印机等固定设备做 DHCP 保留；接入层做 IP-MAC 绑定；冲突 ARP 表项用 reset arp 或等待老化清除。

## 无线终端频繁掉线

- 现象：同一 AP 下多台终端 5 分钟内反复掉线重连，或终端显示已连接但无法获取地址。
- 排查步骤：
  1. AC 上执行 display ap all（华为）、display wlan ap all（华三）、show ap summary（思科、锐捷），看 AP 是否频繁上下线、在线时长是否刚复位。
  2. 执行 display station all（华为）、show wireless client summary（思科）看终端信号强度、重传率和关联 AP，信号低于 -75dBm 会频繁漫游。
  3. 查 AP 供电：PoE 端口功率不足时 AP 反复重启，交换机上 display poe interface 看实际供电功率与 AP 额定功率是否匹配。
  4. 用频谱或信道扫描看 2.4G 信道是否重叠，相邻 AP 同信道会互相压制。
- 处置：高密度区把终端引导到 5G 并关闭 2.4G 低速率；AP 反复重启先解决 PoE 供电（换 PoE+ 端口或本地供电）；调整发射功率和信道，相邻 AP 错开；AP 固件与 AC 版本不匹配时统一版本。

## 跨 VLAN 不通

- 现象：同网段互 ping 正常，跨网段不通，网关能 ping 通但目标网段不通。
- 排查步骤：
  1. 在三层设备执行 display ip routing-table（华为、华三）或 show ip route（锐捷、思科），确认是否存在目标网段路由及下一跳。
  2. 执行 display vlan 确认端口已加入正确 VLAN，接入口应为 untagged、级联口应为 tagged。
  3. 级联口执行 display port vlan 或 show interfaces trunk，确认 VLAN 允许列表包含目标 VLAN。
  4. 检查防火墙上是否有对应网段的安全策略，以及终端自身的子网掩码和网关是否配错。
- 处置：补建 VLAN 与对应三层接口地址；级联口补 allow-pass vlan；路由缺失补静态路由或让路由协议发布网段；策略阻断按最小放通原则加规则。

## 巡检采集超时或拿不到数据

- 现象：巡检记录里该设备的「采集连接」一项异常，其余项目为空或部分为空。
- 排查步骤：
  1. 巡检平台看这台设备的 connection_type：ssh 表示只走命令行，snmp 表示只走 SNMP，hybrid 表示两者都用，auto 由平台判断。
  2. 在采集服务器执行 snmpwalk -v2c -c 社区名 设备IP 1.3.6.1.2.1.1.5.0，能取到设备名说明 SNMP 通；超时则查设备 ACL 是否放通采集服务器地址。
  3. SNMPv3 设备核对认证与加密：平台里 snmp_security_level 为 authPriv 时必须同时配置认证密码和隐私密码，缺一个就连不上。
  4. SSH 采集失败时手工 ssh 登录一次，确认账号权限、是否限制并发会话、是否被 AAA 锁定。
- 处置：ACL 放通采集服务器；社区名或 v3 口令按设备实际值校正；SNMP 凭据不能写进采集模板（平台明确禁止），要改设备基本配置里的凭据；设备侧限制并发会话时放通采集账号。

## 服务器或存储磁盘空间不足

- 现象：巡检 storage_status 项报异常（默认阈值 90%），应用写文件失败或录像中断。
- 排查步骤：
  1. df -h 看是哪个分区满，注意 /var、/tmp、/home 常被单独分区。
  2. du -sh /* 2>/dev/null | sort -h 逐层下钻找占用最大的目录。
  3. lsof | grep deleted 查是否被已删除但仍被进程持有的文件占满，这种情况 df 显示满但 du 加起来对不上。
  4. 录像类设备看录像计划是否把保留天数设得过长，超出磁盘容量。
- 处置：清理或迁移大文件；修 logrotate 的轮转与保留份数；对持有已删除文件的进程做 reload 或重启；录像设备下调保留天数或扩容；临时扩容后要复查增长速率，避免一周后再次告警。

## 告警发不出去

- 现象：告警事件状态是 failed 或 partial，飞书、钉钉或邮件渠道没收到消息。
- 排查步骤：
  1. 巡检平台告警渠道页面看该渠道 is_enabled 是否开启，webhook 地址和加签密钥是否填全。
  2. 看该事件下每条投递记录的 error_summary 字段，里面保存了上游返回的错误摘要。
  3. 飞书自定义机器人最容易漏两件事：安全设置里的关键词必须出现在消息正文中，开启签名校验时时间戳和签名要按官方算法生成。
  4. 邮件渠道核对 SMTP 主机名格式是否被平台接受（含下划线或非法字符会被拒），以及端口与加密方式是否匹配。
- 处置：修正 webhook 与密钥后手工重发；单条投递的重试次数上限是 5 次，超过上限状态变为 failed 不再自动重试，要人工重新触发；渠道被禁用时改 is_enabled 并确认策略里已勾选该渠道。

## 配置变更后业务中断

- 现象：变更操作完成后部分业务不通，或设备行为与变更前不一致。
- 排查步骤：
  1. 巡检平台的配置备份里找到该设备最近一次变更前后的两份配置，对比差异项。
  2. 关注差异里的接口 shutdown、VLAN 允许列表、ACL 条目顺序、路由协议 network 声明，这几类改动最容易打断业务。
  3. 确认变更是否在维护窗口内执行：窗口内的告警仍会记录为待发送，但不会推送，容易被误判成「没出事」。
- 处置：按差异回滚变更项，不要整份配置覆盖回去（会连带回滚其他正常变更）；回滚后重新巡检一次确认指标恢复；后续变更先在维护窗口里登记，避免告警风暴掩盖其他设备的真实故障。

## 广播风暴与网络环路

- 现象：整层网络变慢甚至瘫痪，交换机 CPU 与端口指示灯同时异常，ping 丢包率高。
- 排查步骤：
  1. 执行 display interface 看广播包速率和占比，广播包超过总流量 5% 基本可以确认有环路或广播型故障。
  2. 执行 display mac-address 看是否有同一 MAC 在多个端口间来回跳变，MAC 漂移是环路的典型特征。
  3. 现场排查是否有人把一根网线的两端都插在同一台交换机上，或私接了无管理功能的交换机和路由器。
  4. 确认生成树状态：display stp brief 看根桥位置与端口角色是否符合预期。
- 处置：先拔掉环路端口止血，再启用 STP 或 RSTP；接入口配置边缘端口并开启 BPDU 保护，收到 BPDU 的接入口直接 err-disabled；开启环路检测作为第二道防线；私接交换机一律清理。
